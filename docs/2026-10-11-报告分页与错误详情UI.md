# 2026-10-11 更新：报告前端分页与错误详情 UI

## 前端分页状态常显

“已生成的报告”列表此前仅在总页数大于 1 时显示分页栏。报告数量不足 10 条时，后端实际上已经按页返回数据，但界面没有任何分页控件，容易误以为前端没有实现分页。

本次调整后：

- 有报告时始终显示“第 X / Y 页”、上一页、页码和下一页
- 只有一页时显示“第 1 / 1 页”，上一页和下一页均为禁用状态
- 多页继续显示当前页、有限页码窗口和省略号
- 无筛选结果时只显示空状态，不显示“第 0 / 0 页”
- 日期或行业筛选仍会回到第 1 页

涉及文件：`frontend/src/components/ReportList.vue`

## 数据源异常改为摘要与折叠详情

AI 报告章节过去会把完整的 `HTTPSConnectionPool`、请求 URL、`RemoteDisconnected` 等底层网络异常直接拼进 Markdown 正文。长 URL 占据大量空间，也可能撑破页面布局。

新生成的报告改为：

- 章节正文只显示“部分数据源暂不可用（N 项），其余数据不受影响”
- 原始错误完整保存在章节的 `data_warnings` 字段中，不截断、不解析、不丢失
- 前端在章节下方显示黄色提示条，完整错误默认收进“查看技术详情”折叠区
- 技术详情使用纯文本插值，并允许任意位置换行，超长 URL 不再撑破页面
- `meta.data_errors` 与 `snapshot.errors` 保持原样，仍可用于完整诊断
- 不修改数据源采集逻辑，也不改变单章重试语义

涉及文件：`backend/app/services/report_generator.py`、`frontend/src/api/types.ts`、`frontend/src/components/AiReport.vue`、`frontend/src/style.css`

## 旧缓存兼容

已有报告缓存没有 `data_warnings` 字段，历史错误仍位于 `data_md` 尾部。本次没有批量改写旧缓存，而是在前端渲染时做严格兼容：

- 仅识别尾部由旧版代码生成的 `> 部分数据源未获取：...` 格式
- 从正文显示中移除该历史错误块
- 将冒号后的完整原文作为一条折叠技术详情
- 不扫描或修改正文中的其他内容
- 不覆盖磁盘上的 JSON / Markdown 缓存文件

因此截图中的旧报告刷新页面后即可获得新 UI，无需重新生成并产生 AI token 费用。
