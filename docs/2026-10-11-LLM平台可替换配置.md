# 2026-10-11 更新：LLM 平台抽象，.env 可整体替换

## 改动内容

原先 AI 分析（旧版短报告 + 十二章全维度报告）硬编码 DeepSeek，本次抽象为通用的 OpenAI 兼容平台配置，本地项目在 `backend/.env` 改三行即可换平台（DeepSeek / 千问 Token Plan / 阿里云百炼 / OpenAI 等任何兼容 `chat/completions` 的平台）。

### 新配置项（backend/.env）

```dotenv
LLM_API_KEY=sk-xxxx
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
# LLM_PROVIDER=            # 可选：平台显示名，不配置则按 base_url 自动推断
```

### 兼容性

未配置 `LLM_*` 时自动回退读取旧版 `DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODEL`，现有 `.env` 无需任何改动即可继续工作；两者同时存在时 `LLM_*` 优先。

### 平台显示名（错误提示与报告 meta 使用）

`LLM_PROVIDER` 显式配置优先；否则按 base_url 推断：含 deepseek → DeepSeek、含 qianwen → 千问、含 aliyuncs → 阿里云百炼、含 openai → OpenAI，其余显示「自定义 LLM」。错误信息、报告 meta 中的 model 字段均已泛化。

## 涉及文件

- `backend/app/core/config.py`：新增 `LLM_PROVIDER / LLM_API_KEY / LLM_BASE_URL / LLM_MODEL` 与 `llm_ready`、`llm_provider_name`；删除 `deepseek_ready`（旧变量回退保留在 config 内）
- `backend/app/services/llm_client.py`：改为通用 OpenAI 兼容客户端，所有错误信息使用平台显示名
- `backend/app/services/ai_analyst.py`：`deepseek_ready → llm_ready`、`DEEPSEEK_MODEL → LLM_MODEL`、`_call_deepseek → _call_llm`
- `backend/app/services/report_generator.py`：报告 meta 的 model 字段改用 `LLM_MODEL`
- `backend/app/api/routes.py`：ai_analysis 的 500/502 判断从 `"DEEPSEEK_API_KEY"` 改为 `"API_KEY"`
- `backend/README.md`：配置示例更新为 `LLM_*` 并说明兼容规则
