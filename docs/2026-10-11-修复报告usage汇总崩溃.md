# 2026-10-11 修复：报告生成 usage 汇总崩溃（int() 参数为 dict）

## 问题现象

点击「生成 AI 全维度分析」后任务失败，报错：

```
int() argument must be a string, a bytes-like object or a real number, not 'dict'
```

## 根因

`report_generator._usage_total()` 对每次 LLM 调用的 usage 字典**所有顶层字段**做 `int()` 求和。DeepSeek 接口现版本的 usage 返回里新增了嵌套对象：

```json
"usage": {
  "prompt_tokens": 5,
  "completion_tokens": 1,
  "total_tokens": 6,
  "prompt_tokens_details": {"cached_tokens": 0},
  ...
}
```

`prompt_tokens_details` 是 dict，`int(dict)` 直接抛 TypeError。十二章点评和综合评估全部生成成功后，在最后汇总用量时崩溃，导致整个任务被标记为 failed（任务文件里各章节状态甚至都是 ok）。千问等平台同样会返回此类嵌套明细，换平台后必现。

## 修复

`backend/app/services/report_generator.py` 的 `_usage_total()`：

- 只汇总「至少出现过一次数值」的字段，嵌套 dict 明细（如 `prompt_tokens_details`）不再进入汇总结果；
- 数值转换加了防御，None、非数字字符串等一律按 0 计，不再抛异常。

## 验证

- 用真实 DeepSeek 返回结构（含嵌套 dict）实测：汇总结果只含 `prompt_tokens / completion_tokens / total_tokens` 等数值字段，求和正确
- mock AI 调用跑完整 `generate_report('300821')` 链路：端到端通过
- `pytest` 19 项全部通过

## 备注

8000 端口的开发进程带 `--reload` 会自动加载修复；此前失败的任务（300821、688825）在页面上重新点击生成即可，任务状态会被覆盖。
