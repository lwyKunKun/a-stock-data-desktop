# 美股中文名称搜索修复与美股页面字段中文化

日期：2026-10-22　版本：v0.6.1

## 一、修复美股中文名称搜索（英伟达 → NVDA）

### 问题现象

Web 端输入「英伟达」获取数据时提示「美股代码格式无效，请输入 AAPL、BRK.B 等代码」。

### 根因（两个叠加缺陷）

1. **后端搜索过滤失效**：东方财富搜索接口 `searchapi.eastmoney.com/api/suggest/get` 的响应契约已变化。实测 2026-10-22 当前美股普通股与相关 ETF 的 `SecurityType` 均为 `"7"`，旧代码按 `SecurityType == "20"` 过滤会把所有候选清空；且普通股与 ETF 的 `SecurityTypeName` 都显示「美股」，无法靠文本区分。
2. **前端提交绕过搜索**：`UsStockSearch.vue` 的回车/「查询」按钮把输入原样当作 ticker 提交，不经过搜索解析，中文名称直接进入 `/api/us/data/{symbol}/collect` 被代码格式校验拒绝。

### 修复内容

- `backend/app/datasources/us/search.py`：普通股判定改为合法美股市场（`MktNum ∈ 105/106/107`）+ `Classify == "UsStock"` + `TypeUS == "1"`（ETF 为 `"5"`），不再依赖 `SecurityType`/`SecurityTypeName`；字段统一转字符串兼容数字/字符串；跳过非 dict 行与缺少 `Code`/`Name` 的记录。
- `frontend/src/components/UsStockSearch.vue`：合法 ticker（与后端同一正则）直接提交；中文或不符合 ticker 规则的输入先调用 `/api/us/search` 并自动选择第一条真实代码，无结果/失败时绝不 emit 原始中文；新增 `AbortController` + 请求序号处理防抖与显式提交的竞态，防重复提交，卸载/改输入时统一取消。
- 新增 `backend/tests/test_us_search.py`：mock 真实响应结构，覆盖 NVDA 返回、ETF 排除（`TypeUS=5` 且 `SecurityTypeName=美股`）、三个市场映射、`SecurityType` 值无关、数字/字符串字段兼容、异常/不完整行排除，并校验 curl 参数与超时。

### 验证

- `英伟达`、`NVDA` 实测均返回 `NVDA / 英伟达 / NASDAQ`，相关 ETF 不进入结果。
- 页面输入「英伟达」回车或点查询：只请求 `/api/us/search?q=英伟达`，随后请求 `/api/us/data/NVDA/...`。
- 边界：英文单词 `NVIDIA` 按合法 ticker 直接提交（语法合法即直查）；东方财富对 `NVIDIA` 当前返回空属数据源行为，不做硬编码映射。

## 二、美股数据看板与报告详情页字段中文化

### 问题现象

美股数据看板与报告详情页的章节表格表头、来源名、状态等直接显示英文字段 key（`marketCap`、`totalRevenue`、`operating_cashflow`、`yahoo`、`sec`、`ok/skipped` 等）。

### 方案

架构为「后端聚合 → 后端生成 Markdown 表格 → 前端渲染」，因此不改 API 原始字段名，只在展示层做映射：

- 新增 `backend/app/services/us_field_labels.py`：集中 key → 中文标签映射（行情、K 线、技术指标、估值、公司档案、SEC 指标、Yahoo 驼峰/东财大写财务字段、来源分组等 140 余条），`label_for()` 未命中原样返回，不猜译。
- `backend/app/services/us_chapter_md.py`：`_dict_table`/`_rows_table` 表头、`### yahoo/eastmoney/sec` 小节标题、`us_ch9` 的 SEC 状态字段与数据源错误 key 全部走映射；SEC 关键事实取每项指标最新一期 `value`（`sec.py` 已按 `(filed, end)` 升序，末项即最新），对非 list 输入防护。
- 新增 `frontend/src/utils/usLabels.ts`：来源/章节/状态映射与格式化函数；`localizeUsTableHeaders()` 只替换 Markdown 表格块首行且整格精确命中的单元格，数据行、正文、未知列不动，含 `\|` 转义的表头整行跳过。
- 前端组件接入（均有 `market === 'US'` 门控，A 股不受影响）：
  - `FullDataPanel.vue`：`source_errors` key 中文、采集进度文案中文（`正在采集美股数据：Yahoo Finance基本面`）、数据表渲染前兜底本地化。
  - `ReportViewer.vue`：新增 `market` prop；表头替换只作用于 `data_md`，AI 点评正文（`comment_md`）不本地化；`Tokens 用量：`、`耗时：` 中文标签。
  - `ReportDetail.vue`：向 `ReportViewer` 显式传 `market`。
  - `DataSourceDisclosure.vue`：`ok/failed/skipped` → `正常/失败/已跳过`。
  - `AiReport.vue`：美股报告生成的当前章节文案中文化。

### 历史归档兼容

数据快照每次加载时从 snapshot 重新渲染 `data_md`，后端改完后当日缓存自动中文；历史归档报告的 `data_md` 已固化英文表头，由前端 `localizeUsTableHeaders` 在渲染时兜底替换，无需迁移归档数据，映射表补充新词条后旧报告同步受益。

### 保留原样

股票代码、公司名、交易所、币种、模型名、URL、SEC 编号（CIK/accn）、SEC XBRL tag 值、错误 message 原文、映射表之外的罕见动态字段（保留英文，避免错误翻译）。

### 验证

- 完整后端测试 `71 passed`（含新增 `test_us_chapter_md.py` 2 项）；前端 `type-check` 与生产构建通过。
- 前端映射逻辑 20 余项断言实测：只改表头行、数据行/正文不变、未知列保留、转义表格跳过、幂等。
- 前后端两份映射表 133 个重叠 key 译法全量比对一致。
- 独立 verification 结论 PASS。
