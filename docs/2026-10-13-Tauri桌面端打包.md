# 2026-10-13 Tauri 桌面端打包方案落地

## 背景与决策

项目此前是前后端分离的 Web 应用（FastAPI + Vue3），本次落地桌面端打包，用户已拍板三个决策：

1. **第一阶段只出 macOS**（本机 Intel x86_64 直接构建，不依赖 CI）
2. **仅自用/小范围分发**，不做代码签名（接受 Gatekeeper 右键打开的代价）
3. **LLM Key 走应用内设置页**，不再手编 .env

技术选型沿用 2026-10-01 已定的 **Tauri 壳 + Vue3 前端**，后端 PyInstaller 打成 sidecar 子进程。

## 架构

```
Tauri 壳（Rust，frontend/src-tauri）
  ├── 启动时选空闲端口（默认 18000 起，DESKTOP_API_PORT 可覆盖）
  ├── 拉起 PyInstaller 后端二进制（sidecar），注入环境变量：
  │     PORT / APP_DATA_DIR / SERVE_STATIC_DIR  ├── 轮询 /api/health 等后端就绪（最长 60 秒）
  ├── 创建窗口：
  │     生产 → http://127.0.0.1:{port}/?client=desktop（后端直接托管前端 dist，/api 相对路径零改造）
  │     开发 → http://localhost:5173/?client=desktop（vite dev，/api 代理到 sidecar 端口）
  └── 退出时 SidecarGuard::drop 自动杀后端子进程；sidecar 日志落盘 app_data/sidecar.log
```

**为什么让后端托管前端而不是 Tauri 内置 webview 加载本地文件**：前端所有 API 调用都是相对路径 `/api`。若由 Tauri 加载本地静态文件，origin 变成 `tauri://localhost`，相对路径全部失效，client.ts 需要引入「Tauri 环境检测 + 绝对地址」逻辑。让后端托管 dist 后，origin 就是 `http://127.0.0.1:端口`，前端代码零改动。

## 数据互通（2026-10-13 后续需求）

用户要求桌面端与 Web 开发模式（uvicorn + npm run dev）共用同一份业务数据（报告缓存、快照、任务状态、索引库），两种形态打开看到的是同一份内容。

数据目录选择规则（`src-tauri/src/main.rs`，优先级从高到低）：

1. **`DESKTOP_DATA_DIR` 环境变量**：显式指定业务数据目录。项目根目录提供 `启动桌面端.command`，把该变量指向项目 `backend/data/` 后启动 .app（注意 `open` 命令无法传递环境变量，脚本直接执行二进制）。
2. **开发模式（cargo tauri dev）默认项目 `backend/data/`**：`CARGO_MANIFEST_DIR` 可推导出项目根，零配置互通。
3. **生产模式探测固定项目目录**：双击 `.app` 时若 `~/a-stock-data-desktop/backend/data` 存在，自动与 Web 端共用。
4. **回退系统 `app_data_dir`**：以上都不满足时保持独立安装包的数据隔离行为。

`shell.lock` / `sidecar.log` 是单实例运行期产物，始终留在系统目录，不进共享数据目录，避免多个入口形态互踩。

已知边界：前端查询历史存在浏览器 / Tauri WebView 各自的 localStorage 里，这部分**不互通**，桌面端和 Web 端各自保留自己的查询历史；LLM 配置在共享数据目录后统一由 Web 端 `.env` 与数据目录 `config.json` 两级兜底。

## 后端改造（Web 开发模式行为完全不变）

| 改动 | 默认行为（Web 开发） | 桌面端行为 |

### LLM 配置优先级

```
进程环境变量（含 backend/.env） > 数据目录 config.json（设置页写入） > 默认值
```

`Settings.LLM_*` 从类属性改为 property，每次访问实时解析——设置页保存后立即生效，无需重启后端。`from_env=true` 时设置页明确提示「保存不生效」。

## 构建流程

```bash
# 1. 打包后端 sidecar（backend/ 目录）
.venv/bin/pyinstaller a_stock_desktop.spec --clean --noconfirm
# 产物 backend/dist/a_stock_desktop（约 35MB，含 pandas/lxml/全套 app 模块）

# 2. 复制到 Tauri binaries（文件名必须带 target 三元组后缀）
cp backend/dist/a_stock_desktop frontend/src-tauri/binaries/a_stock_desktop-x86_64-apple-darwin

# 3. 构建 dmg（frontend/ 目录，自动先跑 npm run build）
cargo tauri build
# 产物 frontend/src-tauri/target/release/bundle/dmg/*.dmg
```

### 开发模式联调

```bash
DESKTOP_API_PORT=18000 cargo tauri dev   # 自动起 vite + sidecar，HMR 可用
```

注意：`tauri dev` 要求 `backend/dist/a_stock_desktop` 已存在（或用 `DESKTOP_BACKEND_BIN` 指定路径）；若 18000 被占用需显式给 Rust 和 vite 传同一个 `DESKTOP_API_PORT`。

### 已验证的坑

1. **PyInstaller 字符串导入**：`uvicorn.run("app.main:app")` 打出来的二进制启动即 `ModuleNotFoundError: No module named 'app'`——必须显式 `from app.main import app`。
2. **函数内惰性 import**：数据源模块在函数内 `import pandas`，静态分析追踪不到，spec 里用 `collect_submodules("app")` 全量收集（这也是首包只有 12MB、重打包 35MB 的原因）。
3. **macOS 无 `timeout` 命令**：验证脚本别用 `timeout 25 ./bin`。
4. **PyInstaller 冷启动约 5–8 秒**（pandas 导入），Tauri 轮询等待上限给了 60 秒。
5. **Tauri externalBin 实际落盘位置**：读 tauri-bundler 源码（`bundle/macos/app.rs`）确认——externalBin 复制到 **`Contents/MacOS/`**（不是 Resources），且**剥掉 target 三元组后缀**（`a_stock_desktop-x86_64-apple-darwin` → `a_stock_desktop`）。运行时定位用 `current_exe()` 所在目录。
6. **Tauri resources 的 `..` 会转义成 `_up_`**：list 形态 `["../dist"]` 落盘为 `Resources/_up_/dist`；map 形态 `{"../dist": "dist"}` 才是干净的 `Resources/dist`。
7. **FastAPI 根路由遮蔽静态托管**：`@app.get("/")` 注册在 `app.mount("/", StaticFiles)` 之前会优先匹配，桌面端打开首页拿到的是 JSON 而不是 index.html——静态托管模式下不注册根路由。
8. **sidecar 孤儿进程：flock 探活是唯一能跨 PyInstaller bootloader 层的方案**。实测依次否决了三种方案：Rust `Drop`/`RunEvent::ExitRequested`（tauri 全局 RUNTIME 持有 App 引用，进程被硬杀时析构不执行）；sidecar 轮询 `getppid()==1`（onefile 是两层进程：壳 → bootloader → python，bootloader 在壳死后继续等 python，python 的 ppid 永远不会变 1）；kqueue `EVFILT_PROC/NOTE_EXIT` 监听父进程（监听对象只能是 bootloader，同样跨不到壳）。最终方案：壳启动时对 `shell.lock` 持 flock 排他锁（内核保证进程死亡即释放），sidecar 守护线程**阻塞式等锁**——锁释放=壳已死（任何死法）→ 立即 `os._exit(1)`。顺带实现了单实例约束：第二个实例启动拿不到锁，静默退出（实测 exit 0 无窗口无 panic）。
